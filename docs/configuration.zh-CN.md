# 配置参数

[English](configuration.md) | 简体中文

配置入口为 [config.example.yml](../config.example.yml)。每条规则只接受自己声明的 options；未知键或错误类型会报错。

## 通用配置

| 键 | 含义 |
| --- | --- |
| `input` | APK 或独立 DEX |
| `output` | 新的输出文件路径；APK 输出未签名 |
| `report` | 可选 JSON 报告路径 |
| `dryRun` | 在内存中执行处理，不生成 APK/DEX，仍可写报告；默认 false |
| `maxRounds` | 每个方法的最大迭代轮数；默认 20 |
| `transformers` | 有序规则列表；省略使用默认流程，空列表关闭全部规则 |

```yaml
input: input.apk
output: output.cleaned.apk
report: report.json
maxRounds: 20
transformers:
  - np.strings
  - np.opaque-predicates
  - np.dispatcher
```

顶层文件路径相对于 YAML 所在目录。CLI 覆盖同名顶层项；`--transformers` 替换规则列表和各规则参数。`classpath` 属于规则参数，按进程工作目录解析，建议填写绝对路径。输出、报告和导出的配置均不覆盖既有文件。

## NP 参数

除 `inlineProtected` 默认为 true 外，布尔参数默认为 false，所有列表默认为空。选择 NP 功能后自动附加一次公共清理；方法隐藏还会附加自身的定义清理。控制流平坦化、花指令和不透明条件保持独立。

| 规则 | 参数 | 含义 |
| --- | --- | --- |
| `np.method-hiding` | `classpath` | Android/JAR 成员元数据路径列表，仅解析 class 元数据 |
| | `inlineProtected` | 允许在 try 中恢复已验证代理，保留原目标操作的业务异常 |
| | `assumeClosedWorld` | 允许自身收尾删除没有外部入口的已记录公开代理定义 |
| | `keepMethods` | 自身收尾必须保留的完整 DEX 方法签名列表 |
| `np.reflection` | `classpath` | Android/JAR 成员元数据路径列表 |
| | `assumeStandardRuntime` | 按已识别 NP 反射缓存语义恢复；启用反射还原时必须明确声明 |
| | `assumeClosedWorld` | 允许检查私有字符串字段及已验证的访问器，满足条件时消除缓存包装 |
| `np.strings` | `assumeClosedWorld` | 允许验证公开守卫获取器后的私有 short 表 |
| | `assumeImmutableTables` | 已确认运行时不变的 short 表精确字段签名列表 |
| | `removeProtectedStringCalls` | 允许自身清理删除 try 中结果无用且已验证的解密调用与相关读取 |
| `np.instructions` | `restoreFloatingPoint` | 按代数关系恢复 float/double 加减展开 |

`np.numbers`、`np.opaque-predicates`、`np.dispatcher` 和 `np.flower` 不接受 options。

`np.dispatcher` 支持在 switch 默认回边和循环头穿插整数、对象及 64 位寄存器搬运。只接受循环前后能证明 selector 一致的有界常量/复制回路，允许暂时复用该寄存器后从未改写的备份恢复；恢复路径时保留循环头的存活赋值。备份被覆盖、未知状态，以及带业务操作或可抛异常指令的默认回路继续保留。

`np.flower` 支持 XOR 两地址指令中将状态复制到另一操作数后回跳的比较链，也允许比较之间穿插整数、对象和 64 位寄存器搬运。比较状态可经整数 MOVE 复制到其他寄存器或复制回来；别名被覆盖后停止跟踪该别名。识别与路径恢复各最多跟踪 128 条指令；逐条保留沿途赋值，只有比较结果确定时才替换跳转。未知状态、默认路径持续循环或无法保持异常处理器的路径仍保留。

还原后的重复、往返 MOVE 可跨跳转清理：相等证明最多递归 64 步，只有所有入边都证明两个寄存器相等时才删除。寄存器覆盖、相关强转、异常入口或无法证明的循环会阻止删除；64 位值同时检查两个寄存器槽，构造器初始化后的显式别名绑定继续保留。

有直接 NP 混淆证据的方法中，如果整数或对象 MOVE 的目标只在条件的一个后继上存活，可将复制延后到该分支，以恢复被提前赋值打断的短路条件。此规则在其他公共清理稳定后执行，避免干扰尚未完成的共享区域展开。最多沿单入口路径检查 64 条指令，源值必须保持不变，目标在沿途不可被观察或改写。异常处理器、构造器初始化、路径合流、循环、监视器和可见调试局部变量会阻止移动；普通调用及其副作用保留原位置，标签、行号和异常范围随原指令保留。宽值复制不参与此规则，每次调用最多移动 64 个复制，方法超过 4096 条指令时跳过。

`np.instructions` 同时规范构造器对象别名：仅在同一基本块内证明多个寄存器来自同一次 `new-instance`、且构造器类型一致时，在构造成功后重新绑定仍被使用的别名。这能避免反编译器合并构造表达式时残留未初始化的 SSA 引用；其他分支入口跳过这些绑定，构造器异常仍进入原处理器。

构造方法在多个分支反复复制同一个 `this` 时，若入口接收者从未改写、别名没有其他定义且赋值前不可被观察，可将这些复制合为入口的一次赋值，避免未初始化接收者的 SSA 合并。正常与异常路径的存活检查都通过后才处理。

以 `not-int` 开头的位运算展开可使用跨基本块证明的整数掩码，恢复 `(~x & k) | (x & ~k)` 形式的 XOR。未知掩码和仍被观察的中间值会阻止对应替换；异常处理器只继承抛异常前未改写的常量。

整数偏移和成对取负可跨越只有单一入口的 goto 边恢复，例如 `(x - 8) + y + 8`、`-(-x - y)`。也支持使用寄存器常量和中间搬运的形式，最多跟踪 64 条指令，保持 32 位整数溢出语义。读取和调用保留原位置；路径合流、循环、被观察或仍存活的中间值，以及异常处理器可能看到的改写值会阻止对应替换。

纯 int/long 运算窗口也会沿单入口 goto 跟踪，恢复被拆块的常量掩码及 `(~x) & x` 等恒等式；最多 12 条纯指令、64 步。按实际执行顺序证明表达式，按指令身份定位改写，支持后续运算在 DEX 中排在前面的情况；跳转标签及调试、异常元数据随原指令位置更新。多入口、未知操作、调用、可抛异常指令或仍被观察的中间值会截断这类窗口。

已证明的常量字符串 getter 即使定义在 NP 辅助类中，也会继续执行字符串恢复和公共清理，处理代理展开后暴露的解密调用。此例外仅适用于模型已证明返回常量的 getter；核心 hash、整数守卫和接受运行时参数的解密器仍遵守原有辅助方法保护。删除调用仍须通过解密、权限、初始化和异常路径检查。

公共清理会删除参数为已知字符串、返回值无用的已验证 hash 辅助调用。有静态初始化块的辅助类仍保留必要的首次调用；同一路径中已成功执行该类的静态调用或静态字段访问后，重复 hash 可以删除，包括 try 内的调用。分支合流要求所有入口均已初始化，异常处理器沿用抛异常前的状态，`const-class` 不算初始化。仍参与计算、参数未知或访问权限无法验证的调用保留。报告分别记录删除数量和因初始化而保留的数量。

try 内结果无用的已验证 NP 整数字段读取，若所有入口都已成功初始化其所属类，也可由公共清理删除，避免重复读取夹住比较链的恢复。首次读取、初始化失败后的异常路径、条件初始化、不合法访问、volatile 字段和可变字段均不会因此获得删除资格；初始化的业务副作用仍由原有首次访问执行。报告使用 `redundant initialized NP field reads removed` 记录此类删除，不需要另设清理模块或开启受保护字符串清理。

所属类若已证明没有初始化业务副作用（无初始化、空初始化或仅构造本类私有 final short 表），结果无用的稳定整数读取也可在 try 内清除，包括首次读取，报告以 `unused harmless NP field reads removed` 记录。业务初始化、非法访问、volatile、可变字段和仍被读取的结果继续保留。共享布尔常量块会在相同异常保护范围内按入口复制，复制内容仅为整数常量与跳转，业务调用及抛异常指令保持原位置，避免代理展开后触发 JADX 的重复区域回退。

DEX 中存在已验证的 NP 辅助家族时，公共清理也会规范没有直接辅助引用的业务方法中的跳转、共享短路分支和 switch 默认边（包括经 goto 中转的默认边）。Optimization 可以只改变这些布局；这里使用控制流证明，不据此删除业务调用或字段读取。共享区域只统计可达前驱，不把不可达的对齐 NOP 当成额外入口，避免复制与不可达代码清理反复触发。没有 NP 辅助家族的原始基线保持原有处理范围。

状态机展开后落在方法尾部的条件判断，如果只有一个直接入口且异常覆盖相同，会移回原来的跳转位置，保留两个分支及其寄存器值。共享判断和异常入口继续保留，业务调用不会因此复制。

共享的空值赋值前缀如果重复检查同一未改写的寄存器，也可以按入口条件展开。仅复制最多 24 条赋值和判断，业务操作保留原位置；没有 try 且最多 1024 条指令的方法才参与共享区域处理。

有直接 NP 混淆证据的方法还可拆开共享的终止路径：最多复制 256 条指令，所有路径均须 return/throw，且内部合流之后不能再有条件判断。每条执行路径仍只执行原有业务操作一次；不跨越 try、循环或监视器，复制后的方法总量也受 1024 条指令上限约束。

共享的数组初始化前缀可按条件入边拆开，支持 `new-array`、`filled-new-array` 及 range 编码。前缀只能包含一次数组创建、常量、复制和跳转，结果指令必须与创建指令成对保留；不能包含业务调用、内部判断或循环。仅处理无 try、无调试条目且不超过 1024 条指令的方法，每条路径的数组分配次数保持不变。

其他公共清理稳定后，还可特化带局部常量的共享终止路径：最多跟踪 128 条指令，后续每个判断都必须由局部常量决定，并且至少消去一个已确定判断。调用、分配与其他业务操作逐条保留；未知调用会使其结果失去常量事实。遇到未知判断、循环、try、监视器、数据载荷或调试条目时保留原路径；不会仅为复制一个普通调用尾部而扩大代码。

复制移动稳定后，32 位整数常量也可延后到唯一需要其值的条件后继。仅接受 `const/4`、`const/16`、`const` 和 `const/high16`，保持原编码；沿单入口路径最多检查 64 条指令，目标不能被提前读取或覆写。异常处理器、构造器初始化、合流、循环、监视器及可见调试局部变量会阻止移动；会抛异常的字符串/类型常量和宽常量不参与。报告单独记录 `integer constants delayed to live conditional edges`。

其他公共清理稳定后，可按逆后序重新排列有直接 NP 证据的方法代码块；后续迭代继续处理由布局暴露的优化窗口。普通入口与异常处理入口分别遍历，使用标签重建跳转和异常区间，并检查每条原指令的异常处理器类型、顺序及对应入口。调试条目和 switch/数组载荷方法保持原布局；超过 4096 条指令或 512 个基本块时保留原布局，收敛仍由方法的 `maxRounds` 限制。类、字段、方法声明和 DEX 归属保持。

旧的显式清理规则继续兼容：`np.cleanup` 接受 `assumeClosedWorld`、`assumeImmutableTables`、`removeProtectedStringCalls`，`np.method-hiding.cleanup` 接受 `assumeClosedWorld`、`keepMethods`。`dex.constant-switch` 和 `dex.unreachable` 不接受 options。旧配置的执行顺序和清理参数优先保留，不会再次自动添加相同清理步骤。

### 方法隐藏与反射

```yaml
- id: np.method-hiding
  options:
    classpath: [/path/to/android.jar]
    inlineProtected: true
- id: np.reflection
  options:
    classpath: [/path/to/android.jar]
    assumeStandardRuntime: true
```

代理识别验证守卫和剩余正文，恢复实际执行的成员操作、字面量或参数转发。访问权限、初始化、同步或异常条件不明时保留。`inlineProtected` 跳过代理守卫后不保证保留守卫的 VM/链接失败行为。

方法隐藏还会按类结构识别 NP 代理家族：公共类直接继承 `Object`、无接口，只有一个公共静态整数字段及可选的私有 final short 表，普通方法均为公共静态方法；同时验证 hash、整数守卫和 short 数组解密方法的语义，并确认存在 String 到 String 的辅助方法。守卫可以读取另一个代理类的字段，类名和方法名不参与判断。叠加初始化或控制流混淆的辅助方法使用已有语义证明。

这些类中的短转发方法无需再带独立守卫，也可还原取表、读字段、调用解密器等多个有序操作。每个方法仍需单独证明完整执行路径，未知分支、递归、同步和受保护调用继续遵守原有限制；类匹配不会证明“防字符串一键解密”方法纯净，也不会授权删除业务操作。核心 hash、守卫和数组解密调用仍由对应功能处理。报告以 `np.class-proxy.trace.v1` 记录类特征及方法证明，复用同一套代理清理。

守卫本身被多层代理包装时，规则会逐层验证其正常返回的整数值，再用于选择外层代理的执行路径；这些包装调用仍保留，以维持初始化及异常行为。路径中已知的 int 运算按 32 位语义折叠，除数为零或操作数未知时不折叠。带较多参数和类型转换的代理也可识别，但仍受 DEX 寄存器与指令编码限制。包含未知业务副作用、循环依赖或不稳定字段的守卫包装不会提供常量事实。

方法隐藏还原会在前 256 个寄存器中寻找连续的空闲工作区，并检查正常路径和异常处理器中的存活值。成员调用参数无法直接编码时，可搬运到连续寄存器后使用 range 调用；实例字段操作可借用空闲的低位寄存器，宽值占用相邻两格。没有足够空间时仍保留代理调用，报告编码或寄存器限制。

报告中的 `NP proxy calls retained (...)` 区分正文证明不足、显式关闭的 try 内展开、静态初始化、成员元数据/权限和编码限制。涉及 Android 成员的代理应配置匹配目标平台的 `android.jar`；元数据补齐后仍会检查访问权限。`inlineProtected` 默认 true，已验证的代理不会仅因调用位于 try 中而保留；展开保留原调用的异常保护范围，并检查异常处理器中的寄存器存活值。可显式设置 false 禁止 try 内展开。保留数量按每个方法的每轮执行记录，同一调用可能重复出现，不能直接相加作为最终残留数。

已确认的 NP 代理类若只有空初始化，或只构造并发布本类私有 final short 表，方法隐藏会复用字符串规则的无业务副作用证明，允许首次调用展开；报告用 `proxyInitialization=verified` 记录，可能改变表分配失败等 VM 行为。初始化包含额外写入、业务调用、异常处理或无法证明的操作时，首次调用仍保留。同一路径已有成功的静态调用或字段访问后，可以还原后续代理。路径证明与 hash 清理共用，分支合流要求所有入口都已初始化，初始化失败的异常路径不会取得该事实。

反射的运行时假设包括目标查找可成功、辅助层没有额外业务副作用、私有缓存未被 JNI/反射/插桩修改。未知 ID、接收者类型或逃逸参数数组保留带校验的回退适配器；业务异常沿原处理器传播。

字符串内容首先通过 `np$resolved$string` 缓存访问器展示。能证明只观察字符串内容时可换成字面量；返回、保存到字段或数组、身份比较以及未知消费者会保留缓存。`TextView.setText` 可能保存对象，不能仅因展示用途就删掉包装。

NP 静态整数守卫字段未编码初始值时，按 DEX 默认零参与常量证明，并接受与显式初值相同的可达写入验证。改变字段的初始化、未知写入和 volatile 字段仍会阻止这项证明。

### 完整程序与 short 表

`assumeClosedWorld` 声明输入包含需要分析的完整应用代码，且相关入口没有来自外部 DEX、动态加载、JNI、反射或框架配置的隐藏观察者。各功能独立读取这个声明；`np.strings` 也将该声明传给它自动安排的公共清理，`np.method-hiding` 将它用于自身定义清理。旧配置若显式写了清理规则，以该规则自身的参数为准。APK 有多个 DEX 本身并不足以证明该条件。

`np.strings` 先恢复明文，自动安排的清理随后删除无用调用，并在全 DEX 收尾回收无引用的已验证 short 表。业务读取、写入、返回逃逸、元数据引用或未知消费者会阻止对应证明。只选择 `np.strings` 也会执行这些清理；仍有引用或证明不足的表保留。

`assumeClosedWorld: true` 不会直接把所有 short 表视为常量。输入存在 JNI、反射或动态加载时，公开获取器的静态验证仍可能被阻止；`private static final short[]` 也只保证字段不能重新赋值，不保证数组元素不变。报告中的 `unproven NP string calls` 表示已识别解密方法，但数组或切片参数仍无法证明。若这些字符串还用于计算控制流状态，它们未解密时，相应的 hash / switch 分发也会保留。

字符串表经过已验证的 `short[]` 强转后仍可用于解密；别名检查也会继续跟踪强转后的写入。已验证的初始化器写入静态表后，原局部数组也保持同一表的身份，支持 `<clinit>` 继续复用它解密。数字字段验证会覆盖后续识别出的 NP 辅助类，仍拒绝不同值写入和 volatile 字段。对无参数的公共字符串获取方法，规则可在已验证路径上推导常量返回值，并向调用方传播，最多迭代八轮以处理嵌套获取器。原获取调用保留，首次类初始化、业务副作用和抛异常的行为仍由它执行；这项返回值证明不用于删除调用。

带参数的公共静态字符串代理也可传播已知表和切片参数，支持 `Object` 到 `short[]` 的强转及已验证守卫。求值限制为八层调用、4096 步；未知参数、不稳定守卫、不兼容强转或递归成环时保留未知结果。原代理调用仍执行，这项证明不会放宽字符串表的可变性条件。

若特定样本公开了加密表、但已确认运行时不会修改它，可配置：

```yaml
- id: np.strings
  options:
    assumeImmutableTables:
      - 'Lexample/Strings;->table:[S'
```

该项是针对精确字段的显式假设；已发现的数组写入仍会拒绝。它不会放宽数组回收或公开代理删除的条件。

### 浮点与受保护调用

```yaml
- id: np.instructions
  options:
    restoreFloatingPoint: true
- id: np.strings
  options:
    removeProtectedStringCalls: true
```

浮点恢复按代数关系简化同一基本块内的零取负、嵌套加减和常量抵消，保留必要转换与字段写入。它可能匹配正常代码中的同类表达式，并改变舍入、正负零、NaN、无穷大和加法结合顺序。例如样本 `testDoublePoint(0.1, 0.2)` 从 `0.8200000000000006` 变为 `0.82`。需要保持当前 APK 浮点行为时使用默认 false；已移除的实验参数 `floatingPointClasses` 不再接受。

`removeProtectedStringCalls` 仅删除已验证、参数有效且结果无用的解密调用与相关读取；业务调用和处理器保留。它不保证保留分配失败、链接失败等 VM 异常行为。报告会记录这两项实际触发的改写。

NP 解密时将成功解密且已验证可删除的调用记录在当前方法事务中，清理直接使用该记录；记录绑定指令身份，随指令移动，不以旧偏移匹配新调用。重建指令或替换调用会使记录失效，下一轮重新验证。`assumeImmutableTables` 同时传给自身清理，避免解密与回收使用不同的表信息。调用删除后继续回收无用的数组和字符串强转、表读取及参数赋值。`removeProtectedStringCalls` 同样处理方法隐藏展开后才出现的解密调用。辅助类允许只有 `return-void` 的空初始化；若仅在 `<clinit>` 构造并发布本类私有 final short 表，允许忽略该初始化的分配行为。含业务调用、其他父类或对外发布的表不适用。

### 代理定义清理

```yaml
- id: np.method-hiding
  options:
    assumeClosedWorld: true
    keepMethods:
      - 'Lexample/Helper;->keep(I)I'
```

清理只消费本次运行提交的恢复证据，核对原始指纹、最终引用、入口和动态访问风险。默认保留公开代理。发生方法回退或未收敛时跳过定义删除；单独对上次输出执行清理不会补认候选，也不删除辅助类或字段。

## 通用字符串模型

```yaml
- id: strings.decrypt
  options:
    xorMethods:
      - 'Lexample/Crypto;->decode(Ljava/lang/String;I)Ljava/lang/String;'
    stringFogXorMethods:
      - 'Lexample/Fog;->decrypt(Ljava/lang/String;Ljava/lang/String;)Ljava/lang/String;'
    # 已确认上述方法无每次调用的业务副作用时，清理已解密的重复调用。
    removeDecryptedCalls: false
```

`xorMethods` 要求 UTF-16 char XOR；`stringFogXorMethods` 要求 Base64 密文和密钥、循环字节 XOR、UTF-8 输出。这些精确签名由配置者确认，不能套用于其他算法。通用模型保留原调用，只替换已知返回结果；NP 专用规则另行校验辅助方法体。

`removeDecryptedCalls: true` 声明配置的解密方法没有每次调用的业务副作用，允许删除参数有效、结果已还原或无用的调用；可能改变分配、链接及 VM 失败行为。默认 false。清理 `xorMethods` / `stringFogXorMethods` 中的精确签名及已验证仅作转发的外层代理；未知参数、无效密文、缺失成员、同步方法、不可访问成员或未证明的业务副作用会阻止删除。

解密时同步记录调用位置、所经叶子解密器和代理依赖，直接用于同次清理，不再重新寻找明文附近的调用。解密器及其依赖的初始化都已证明没有业务副作用时，首次有效调用也可删除。验证沿静态方法、构造器和可确定目标的实例方法追踪依赖，最多 64 个方法、8192 条指令；不执行目标代码。初始化器只接受空操作、私有 final 基本类型常量表，以及通过空构造器创建、没有终结器的无状态对象；同时检查父类和接口。平台依赖限定为明确的字符串、Base64、UTF-8 和数组复制操作。业务初始化、未知库方法或无法确定目标的虚调用会阻止这项首次删除证明。

初始化无法完整证明时，仍保留每条路径上第一次参数有效且正常完成的叶子解密调用。已验证代理的正常返回可提供其叶子解密器已完成的事实。参数未知的调用即使正常返回，也可能提前返回 null，不能提供解密成功的事实。分支合流要求所有入口都已验证并成功调用同一个精确签名，异常处理器沿用抛异常前的事实。代理另外检查原方法所经路径的副作用、强转、字段读取和类初始化，业务调用仍保留。删除调用后同时回收无用的参数赋值，仍需要的明文和业务异常处理保留。报告记录 `decrypted calls removed`、`proven decryptor proxy calls removed`、`decrypted calls removed with proven harmless dependency initialization` 与保留原因。

隐藏方法展开产生的 `String` 强转会保留已经证明的字符串常量，使 NP 内层明文可以继续交给 StringFog 解密。输出中仍有解密调用不一定表示结果未恢复：调用之后的 `const-string` 是替换后的已知返回值。

隐藏代理因 try 保护或首次类初始化而保留时，`strings.decrypt` 也会沿静态字符串转发链推导返回值，支持 `Object` 参数强转和已验证 NP 整数守卫的嵌套代理。只跟踪能到达已配置解密签名的公共静态方法；单个方法最多 512 条指令、调用链最多八层、单次求值最多 4096 步。分支条件或解密参数未知、递归成环、代理内部包含异常处理、宽参数或同步方法时，不替换其未知返回值。默认保留原代理调用；启用清理后，只删除另行通过副作用与初始化验证的调用。

JADX 中只有调用、没有接收结果的解密语句，可能是为保留这些行为而留下的无用结果调用；规则只替换实际接收的返回值，不为它插入随后会被清理的无用明文。

分支汇合处的密文或密钥不同，但各入口都能分别解密时，会在对应路径写入明文，保留参数之间的对应关系和原解密调用。最多检查八个入口及 32 条公共前缀指令；未知输入、不同异常保护范围、无法隔离的控制流或缺少可编码的临时寄存器时跳过。报告记录 `branch string results restored (calls retained)`。

异常路径只继承抛异常指令未改写的局部常量；catch 中重新赋值的密文或密钥可通过上述逐入口证明恢复，仍保留异常路径的实际选择。

默认配置中 `strings.decrypt` 没有算法签名，因此不会改写字符串。叠加 NP 和 StringFog 的 APK 需要分别满足 NP 表的验证条件，并配置经过核实的 `stringFogXorMethods`；只启用其中一项，不能解除另一层加密。

## 报告与边界

`methods` 记录每个方法的规则步骤、跳过原因、回退和收敛状态；`dexSteps` / `dexEdits` 记录收尾改动；`methodEvidence` 包含候选代理、已提交替换和删除/保留决策。方法未改写可能表示无混淆，也可能是证明条件不足。

APK 的所有根目录 `classes*.dex` 联合分析后按原类归属写回。资源、Manifest、assets 和 native 库内容保留，ZIP 重建并移除失效签名。重复类、混合 DEX 版本和超出写出限制会报错；不合并 AAB、APKS 或 split APK 集合。
